Step 6b1 week

The public viewer

Build the only public page: a read-only, IRC-style viewer of every channel, with a text status bar for live matches in #games.

The viewer is how people see the project. It shows every public channel as plain, well-set text, and in #games a status bar for the running match. It has no event handlers at all, so nothing a visitor sends can do anything.

6b.1 Add match state to the contract

The page shouldn't parse "Round 2 of 5" out of chat text. Add a structured snapshot to the stream instead. Adding a field with a new number is non-breaking, so buf breaking stays green.

Exercise: Snapshot and the hub

  1. Write func (m *Match) Snapshot() State. Copy RoundWins into a new map, so the receiver can't change the match's map.
  2. In the hub, pass m to handleEffect. On StartTimer, record deadline = time.Now().Add(After). On Say, include m.Snapshot() (converted to the proto type) and the deadline in the broadcast.

Why is reading m from handleEffect safe? Because the runner calls out on its own goroutine, the only one that ever touches m.

Solution: the hub changes 
func (h *Hub) handleEffect(ch string, m *match.Match, e match.Effect) {
    switch e := e.(type) {
    case match.StartTimer:
        h.mu.Lock()
        h.state(ch).deadline = time.Now().Add(e.After)
        h.mu.Unlock()
    case match.Say:
        h.broadcast(ch, e.Text, m.Snapshot())
    case match.RoundWon, match.MatchWon:
        // Step 9: award XP and publish level-ups here.
    }
}

func toProto(s match.State, deadline time.Time) *gamev1.MatchState {
    wins := make(map[string]int32, len(s.RoundWins))
    for p, w := range s.RoundWins {
        wins[string(p)] = int32(w)
    }
    return &gamev1.MatchState{
        Phase: s.Phase, Round: int32(s.Round), TotalRounds: int32(s.TotalRounds),
        Lo: int32(s.Lo), Hi: int32(s.Hi), CurrentPlayer: string(s.CurrentPlayer),
        TurnDeadlineUnixMs: deadline.UnixMilli(), RoundWins: wins,
    }
}

6b.5 The LiveView

lib/chat_web/live/channel_live.ex
defmodule ChatWeb.ChannelLive do
  use ChatWeb, :live_view
  alias Chat.Rooms

  @impl true
  def mount(_params, _session, socket) do
    {:ok, assign(socket, channels: Rooms.list_public_channels(), room: nil, match: nil, nicks: [])}
  end

  @impl true
  def handle_params(%{"channel" => name}, _uri, socket) do
    case Rooms.get_channel(name) do
      %{public: true} = channel ->
        if connected?(socket), do: switch_subscription(socket.assigns.room, name)

        {:noreply,
         socket
         |> assign(room: name, topic: channel.topic, page_title: "#" <> name, nicks: nicks(name))
         |> stream(:messages, Rooms.recent(name, 100), reset: true)}

      _ ->
        {:noreply, push_navigate(socket, to: ~p"/c/general")}
    end
  end

  def handle_params(_params, _uri, socket), do: {:noreply, push_patch(socket, to: ~p"/c/general")}

  # No handle_event/3 anywhere: visitors can't send anything.

  @impl true
  def handle_info({:new_msg, msg}, socket), do: {:noreply, stream_insert(socket, :messages, msg)}
  def handle_info({:match_state, state}, socket), do: {:noreply, assign(socket, match: state)}

  def handle_info(%Phoenix.Socket.Broadcast{event: "presence_diff"}, socket),
    do: {:noreply, assign(socket, nicks: nicks(socket.assigns.room))}

  defp switch_subscription(old, new) do
    if old, do: Phoenix.PubSub.unsubscribe(Chat.PubSub, "room:" <> old)
    Phoenix.PubSub.subscribe(Chat.PubSub, "room:" <> new)
  end

  defp nicks(room), do: ChatWeb.Presence.list("room:" <> room) |> Map.keys() |> Enum.sort()
end

    </aside>
  </div>

attr :id, :string, required: true
attr :msg, :map, required: true

def log_line(assigns) do
  ~H"""
  <p id={@id} class={["irc-line", system?(@msg) && "is-system", @msg.kind == "service" && "is-service"]}>
    <time class="irc-dim">{Calendar.strftime(@msg.at, "%H:%M")}</time>
    <span :if={!system?(@msg)} class={"irc-nick nick-#{nick_color(@msg.nick)}"}>&lt;<span
      :if={@msg.kind == "bot"} class="irc-lv">[Lv {@msg.level}] </span>{@msg.nick}&gt;</span>
    <span class="irc-body">{@msg.body}</span>
  </p>
  """
end

defp system?(msg), do: String.starts_with?(msg.body, "***")
defp nick_color(nick), do: :erlang.phash2(nick, 6)

{@msg.body} is HTML-escaped automatically. Never use raw/1 on anything a bot wrote: bots are LLMs and will eventually output <script>.

Exercise: status_bar and range_bar

  • status_bar renders one line: Round 2/5 │ Turn: vex (12s) │ Range 31–49 │ pip 1 · vex 1. The countdown is an element with phx-hook=".Countdown" and data-deadline={@match.turn_deadline_unix_ms}.
  • range_bar renders a 50-character text bar for 1–100: ▓ for numbers still possible (between lo and hi), · for ruled out, with the numbers at each end. Put it in a <pre> with an aria-label that says the range in words.
Solution: range_bar 
attr :lo, :integer, required: true
attr :hi, :integer, required: true

def range_bar(assigns) do
  cells =
    for i <- 0..49, into: "" do
      n = 1 + div(i * 100, 50)
      if n >= assigns.lo and n <= assigns.hi, do: "▓", else: "·"
    end

  assigns = assign(assigns, :cells, cells)

  ~H"""
  <pre class="irc-range" aria-label={"Still possible: #{@lo} to #{@hi}"}>1 {@cells} 100</pre>
  """
end

6b.7 Two colocated hooks (full code)

LiveView 1.1+ lets you write a hook's JavaScript right next to the markup that uses it. The countdown ticks in the browser, so the server doesn't send a message every second.

<span id="countdown" phx-hook=".Countdown" data-deadline={@match.turn_deadline_unix_ms}></span>
<script :type={Phoenix.LiveView.ColocatedHook} name=".Countdown">
  export default {
    mounted() { this.tick(); this.timer = setInterval(() => this.tick(), 250) },
    updated() { this.tick() },
    destroyed() { clearInterval(this.timer) },
    tick() {
      const ms = Number(this.el.dataset.deadline) - Date.now()
      this.el.textContent = ms > 0 ? `${Math.ceil(ms / 1000)}s` : ""
    }
  }
</script>

<script :type={Phoenix.LiveView.ColocatedHook} name=".AutoScroll">
  export default {
    mounted() { this.stick = true; this.el.addEventListener("scroll", () => {
      this.stick = this.el.scrollTop + this.el.clientHeight >= this.el.scrollHeight - 40 }) },
    updated() { if (this.stick) this.el.scrollTop = this.el.scrollHeight }
  }
</script>

The countdown trusts the visitor's clock. A few seconds of skew is harmless here; for anything that mattered you'd send "seconds remaining" instead of a timestamp.

6b.9 Harden the public page

  • Set a strict Content Security Policy in the :browser pipeline with put_secure_browser_headers/2.
  • Make sure the public endpoint has no socket "/socket" line: only the LiveView socket (/live) is mounted there.
  • Never render bot text with raw/1.
  • If abuse shows up, cap LiveView connections per IP at the proxy rather than in the app.

QA for this step

Automated

  • Phoenix.LiveViewTest: the page renders every public channel; live(conn, "/c/nope") redirects to #general; a broadcast {:new_msg, ...} appears in render(view).
  • A test that render_click/2 on any element fails, because there's no handle_event.
  • An XSS test: a message body of <img src=x onerror=alert(1)> appears escaped in the rendered HTML.

Manual

  • Work through the viewer checklist on a phone and a laptop.

Break it on purpose

  • Open the viewer in 20 tabs and post a burst of messages: every tab stays in sync and memory stays flat.

Checkpoint

A match between bots is easy to follow on a phone and a laptop, switching channels doesn't reload the page, the countdown is smooth with no server ticks, and the browser's network panel shows nothing but the LiveView socket and static assets.
