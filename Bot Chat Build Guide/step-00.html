Step 01 evening

Tools and repo setup

Install the toolchain, pin versions, and create the monorepo every later step builds in.

Learn first

  • Git basics if needed: Pro Git, chapters 1–3.
  • Docker: images vs containers, docker run, docker ps — Docker get started.
  • mise: a version manager that pins Erlang, Elixir, Go and Python per project from one file.

0.1 Install the base tools

Install these once on your machine:

Tool Why Install
Git Version control git-scm.com
Docker Desktop (or OrbStack / Colima on macOS) Postgres locally, Compose in Step 12 docs.docker.com
mise Language versions mise.jdx.dev
VS Code (or your editor) Editing code.visualstudio.com

Editor extensions: an Elixir language server (ElixirLS or Expert), the official Go extension, Python + Ruff, and Buf for .proto files.

0.2 Create the repo and pin versions

One Git repository holds every service (a monorepo), so a change to the shared .proto contract updates all of them in one commit.

mkdir botchat && cd botchat
git init
.mise.toml
# Everyone who clones the repo gets exactly these versions.
[tools]
erlang = "28"
elixir = "1.20"
go = "1.26"
python = "3.12"
uv = "latest"

mise install          # compiles/downloads each tool; Erlang takes a few minutes
mise ls               # confirm what's active in this folder

Why pin versions?

"Works on my machine" usually means "my machine has a different version". Pinning makes your laptop, CI and Docker builds agree.

0.3 Lay out the folders

mkdir -p proto chat game bots lambdas/announcer infra

botchat/
  proto/              # .proto contracts shared by chat and game
  chat/               # Elixir/Phoenix app (Step 2)
  game/               # Go game service (Step 4)
  bots/               # Python bot runner (Step 7)
  lambdas/announcer/  # Go Lambda (Step 10)
  infra/              # Terraform (Step 11)
  docker-compose.yml  # local dev (Step 12)
  README.md
.gitignore
# secrets
.env
*.env
!.env.example

# build output
_build/
deps/
bootstrap
function.zip
.terraform/
*.tfstate*
__pycache__/
.venv/

Secrets never go in Git

You'll have 42 bot tokens, an OpenRouter key and AWS keys by the end. They live in .env files locally and in your host's secret store in production. The .gitignore above is your first line of defense; add a pre-commit secret scanner if you want a second.

0.4 Write the README skeleton

README.md
# botchat

An IRC-style chat where AI bots talk and play Guess the Number.

| Service | Language | Folder |
| --- | --- | --- |
| chat | Elixir / Phoenix | `chat/` |
| game | Go | `game/` |
| bots | Python | `bots/` |
| announcer | Go (AWS Lambda) | `lambdas/announcer/` |

## Run locally
(filled in during Step 12)

git add -A && git commit -m "Set up monorepo layout and tool versions"

Exercise

Create a GitHub repository and push to it. Then clone it into a second folder, run mise install there, and confirm the versions match. This is exactly what a new contributor (or CI) will do.

QA for this step

Automated

  • git check-ignore .env bots/.env prints both paths (secrets can't be committed).

Manual

  • Clone into a fresh folder and run mise install: identical versions.

Break it on purpose

  • Commit a fake .env on a throwaway branch: it should be ignored. If you add gitleaks, a fake sk-or-... key in a file should fail the pre-commit hook.

Checkpoint

elixir --version, go version, python --version and docker run hello-world all work inside the repo folder, and your first commit is on GitHub.
