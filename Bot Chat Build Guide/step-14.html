Step 141–2 weeks

Observability and CI

Follow one guess through every service in a single trace, and make every push prove that all four parts still build and pass their tests.

A trace that follows one bot's guess from its WebSocket, through gRPC, SNS, SQS and the Lambda, and back into chat is the best demo this project can produce. CI makes sure that demo keeps working.

Learn first

  • OpenTelemetry concepts: traces, spans, context propagation, the traceparent header.
  • Per language: Go and otelgrpc; Erlang/Elixir; Python.
  • Jaeger getting started to view traces locally.
  • GitHub Actions quickstart and path filters.

14.1 Run Jaeger locally (full code)

docker-compose.yml add a service
  jaeger:
    image: jaegertracing/jaeger:latest   # pin a 2.x tag from Docker Hub
    ports:
      - "16686:16686"                    # UI: http://localhost:16686

Every service exports to http://jaeger:4317 (OTLP over gRPC) via the standard OTEL_EXPORTER_OTLP_ENDPOINT environment variable, and names itself with OTEL_SERVICE_NAME.

14.2 Trace the game (full code)

cd game
go get go.opentelemetry.io/otel go.opentelemetry.io/otel/sdk \
  go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc \
  go.opentelemetry.io/contrib/instrumentation/google.golang.org/grpc/otelgrpc
cmd/server/otel.go
package main

import (
    "context"

    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc"
    "go.opentelemetry.io/otel/propagation"
    sdktrace "go.opentelemetry.io/otel/sdk/trace"
)

// setupTracing reads OTEL_EXPORTER_OTLP_ENDPOINT and OTEL_SERVICE_NAME from the environment.
func setupTracing(ctx context.Context) (shutdown func(context.Context) error, err error) {
    exp, err := otlptracegrpc.New(ctx)
    if err != nil {
        return nil, err
    }
    tp := sdktrace.NewTracerProvider(sdktrace.WithBatcher(exp))
    otel.SetTracerProvider(tp)
    otel.SetTextMapPropagator(propagation.TraceContext{})
    return tp.Shutdown, nil
}

Then create the server with a stats handler, and every RPC gets a span whose parent comes from the caller's traceparent:

s := grpc.NewServer(
    grpc.StatsHandler(otelgrpc.NewServerHandler()),
    grpc.UnaryInterceptor(unary),
    grpc.StreamInterceptor(stream),
)

14.3 Carry the trace through SNS and SQS

gRPC propagates trace context for you. Queues don't: you put it in a message attribute yourself.

internal/events/events.go in SNSPublisher.Publish
carrier := propagation.MapCarrier{}
otel.GetTextMapPropagator().Inject(ctx, carrier) // adds "traceparent" (and maybe "tracestate")

attrs := map[string]types.MessageAttributeValue{
    "type": {DataType: aws.String("String"), StringValue: aws.String(e.Type)},
}
for k, v := range carrier {
    attrs[k] = types.MessageAttributeValue{DataType: aws.String("String"), StringValue: aws.String(v)}
}

With raw message delivery, SNS passes these attributes to SQS as message attributes (up to 10).

Exercise: extract on the other side

  • Lambda: read rec.MessageAttributes["traceparent"].StringValue, put it in a propagation.MapCarrier, call Extract, and start the handler's span from the returned context. Pass that context on, and inject it again into the chat-notices message's attributes.
  • Broadway: set attribute_names: :all and message_attribute_names: :all on BroadwaySQS.Producer, read traceparent from the message metadata, and use :otel_propagator_text_map.extract/1 before starting a span in handle_message/3.
  • Chat → game: add OpenTelemetry to the Elixir gRPC client (via an interceptor or by injecting into the call's metadata) so SubmitInput spans link to the bot's message.

14.4 Trace chat and bots

  • Chat: add opentelemetry, opentelemetry_api, opentelemetry_exporter, opentelemetry_phoenix and opentelemetry_ecto per the Erlang/Elixir getting started guide, and call each instrumentation's setup/0 in Application.start/2.
  • Bots: add opentelemetry-sdk and opentelemetry-exporter-otlp, start a span around each speak and take_turn with attributes bot.nick, llm.model, llm.cost_usd, and send the traceparent in the message payload so chat can link to it.

Log the trace ID on every log line in all three languages. Then a log line leads you straight to its trace.

14.5 CI: one workflow per service (full code)

Each workflow runs only when its own folder (or the shared contract) changes.

.github/workflows/game.yml
name: game
on:
  push: { branches: [main], paths: ["game/**", "proto/**", ".github/workflows/game.yml"] }
  pull_request: { paths: ["game/**", "proto/**", ".github/workflows/game.yml"] }

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: bufbuild/buf-action@v1
        with:
          breaking_against: "${{ github.event.repository.clone_url }}#branch=main"
      - uses: actions/setup-go@v5
        with: { go-version-file: game/go.mod }
      - run: go vet ./... && go test -race ./...
        working-directory: game
.github/workflows/chat.yml
name: chat
on:
  push: { branches: [main], paths: ["chat/**", "proto/**", ".github/workflows/chat.yml"] }
  pull_request: { paths: ["chat/**", "proto/**", ".github/workflows/chat.yml"] }

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:17
        env: { POSTGRES_PASSWORD: postgres }
        ports: ["5432:5432"]
        options: >-
          --health-cmd pg_isready --health-interval 2s --health-retries 20
    env:
      MIX_ENV: test
    steps:
      - uses: actions/checkout@v4
      - uses: erlef/setup-beam@v1
        with: { version-file: .mise.toml, version-type: strict }   # or pin otp-version/elixir-version
      - run: mix deps.get && mix format --check-formatted && mix compile --warnings-as-errors && mix test
        working-directory: chat
.github/workflows/bots.yml
name: bots
on:
  push: { branches: [main], paths: ["bots/**", ".github/workflows/bots.yml"] }
  pull_request: { paths: ["bots/**", ".github/workflows/bots.yml"] }

jobs:
  test:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: bots } }
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
      - run: uv sync --frozen
      - run: uv run ruff check . && uv run pytest
.github/workflows/infra.yml
name: infra
on:
  pull_request: { paths: ["infra/**", ".github/workflows/infra.yml"] }

jobs:
  validate:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: infra } }
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3
      - run: terraform fmt -check -recursive
      - run: terraform init -backend=false && terraform validate

Check each action's README for its current major version before you copy these; they move about once a year. erlef/setup-beam can read versions from a .tool-versions file; if it doesn't accept .mise.toml in your version, pin otp-version and elixir-version directly.

Exercise: make CI earn its keep

Break something on a branch in each service (a failing test, an unformatted file, a renamed proto field) and open a pull request. Each should turn exactly one workflow red. Then add a branch protection rule on main that requires all four checks.

Manual

  • In Jaeger, one level-up shows a single trace from the bot's guess to the *** notice.

Break it on purpose

  • Do every chaos drill once in production and record what happened in your README. Add the DLQ alarms and confirm one fires.

Checkpoint

Jaeger shows one trace for a level-up that spans game, SNS/SQS, the Lambda and chat; and a failing test in any service turns its pull request check red.
