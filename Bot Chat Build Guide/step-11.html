Step 111 week

Infrastructure as code with Terraform

Describe every AWS resource in code: the topic, three queues with dead-letter queues, the Lambda, and least-privilege credentials for each service.

Everything you clicked or typed in Steps 8–10 becomes code in infra/. You can rebuild it, review changes in a pull request, and tear it all down with one command.

Learn first

  • Get started with Terraform on AWS: init, plan, apply, state, variables, outputs.
  • AWS provider docs: pin ~> 6.0.
  • S3 backend with use_lockfile = true for state locking.
  • Modules: you'll write one small one.

11.1 Bootstrap remote state (once, by hand)

Terraform records what it created in a state file. Keep it in S3, versioned, so it survives your laptop.

aws s3api create-bucket --bucket botchat-tfstate-<you> --region us-east-1
aws s3api put-bucket-versioning --bucket botchat-tfstate-<you> \
  --versioning-configuration Status=Enabled
infra/main.tf
terraform {
  required_version = ">= 1.10"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
  backend "s3" {
    bucket       = "botchat-tfstate-<you>"
    key          = "botchat/terraform.tfstate"
    region       = "us-east-1"
    use_lockfile = true
  }
}

provider "aws" {
  region = "us-east-1"
  default_tags {
    tags = { project = "botchat" }
  }
}

resource "aws_sns_topic" "game_events" {
  name = "game-events"
}

cd infra && terraform init && terraform plan

11.2 A reusable fan-out queue module (full code)

Two queues subscribe to the topic and need the same four parts: a queue, its dead-letter queue, a policy letting only this topic write to it, and a filtered, raw-delivery subscription. Write that once.

infra/modules/fanout_queue/main.tf
variable "name" {
  type = string
}

variable "topic_arn" {
  type = string
}

variable "event_types" {
  type        = list(string)
  description = "Only messages whose `type` attribute is in this list are delivered."
}

variable "visibility_timeout" {
  type    = number
  default = 30
}

resource "aws_sqs_queue" "dlq" {
  name                      = "${var.name}-dlq"
  message_retention_seconds = 1209600 # 14 days to investigate failures
}

resource "aws_sqs_queue" "this" {
  name                       = var.name
  visibility_timeout_seconds = var.visibility_timeout
  redrive_policy = jsonencode({
    deadLetterTargetArn = aws_sqs_queue.dlq.arn
    maxReceiveCount     = 5
  })
}

data "aws_iam_policy_document" "allow_topic" {
  statement {
    effect    = "Allow"
    actions   = ["sqs:SendMessage"]
    resources = [aws_sqs_queue.this.arn]
    principals {
      type        = "Service"
      identifiers = ["sns.amazonaws.com"]
    }
    condition {
      test     = "ArnEquals"
      variable = "aws:SourceArn"
      values   = [var.topic_arn]
    }
  }
}

resource "aws_sqs_queue_policy" "this" {
  queue_url = aws_sqs_queue.this.id
  policy    = data.aws_iam_policy_document.allow_topic.json
}

resource "aws_sns_topic_subscription" "this" {
  topic_arn            = var.topic_arn
  protocol             = "sqs"
  endpoint             = aws_sqs_queue.this.arn
  raw_message_delivery = true
  filter_policy        = jsonencode({ type = var.event_types })
}

output "queue_url" {
  value = aws_sqs_queue.this.url
}

output "queue_arn" {
  value = aws_sqs_queue.this.arn
}
infra/queues.tf
module "level_updates" {
  source      = "./modules/fanout_queue"
  name        = "level-updates"
  topic_arn   = aws_sns_topic.game_events.arn
  event_types = ["player.leveled_up"]
}

module "announcements" {
  source             = "./modules/fanout_queue"
  name               = "announcements"
  topic_arn          = aws_sns_topic.game_events.arn
  event_types        = ["player.leveled_up"]
  visibility_timeout = 60 # at least 6x the Lambda's 10 s timeout
}

# Not subscribed to SNS: only the Lambda writes here, only chat reads.
resource "aws_sqs_queue" "chat_notices_dlq" {
  name = "chat-notices-dlq"
}

resource "aws_sqs_queue" "chat_notices" {
  name = "chat-notices"
  redrive_policy = jsonencode({
    deadLetterTargetArn = aws_sqs_queue.chat_notices_dlq.arn
    maxReceiveCount     = 5
  })
}

terraform init      # picks up the new module
terraform apply

11.3 The Lambda (full code)

infra/lambda.tf
locals {
  announcer_zip = "${path.module}/../lambdas/announcer/function.zip"
}

data "aws_iam_policy_document" "lambda_assume" {
  statement {
    actions = ["sts:AssumeRole"]
    principals {
      type        = "Service"
      identifiers = ["lambda.amazonaws.com"]
    }
  }
}

resource "aws_iam_role" "announcer" {
  name               = "botchat-announcer"
  assume_role_policy = data.aws_iam_policy_document.lambda_assume.json
}

# Read/delete from SQS and write CloudWatch logs
resource "aws_iam_role_policy_attachment" "announcer_sqs" {
  role       = aws_iam_role.announcer.name
  policy_arn = "arn:aws:iam::aws:policy/service-role/AWSLambdaSQSQueueExecutionRole"
}

# ...and send to exactly one queue
resource "aws_iam_role_policy" "announcer_send" {
  role = aws_iam_role.announcer.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = "sqs:SendMessage"
      Resource = aws_sqs_queue.chat_notices.arn
    }]
  })
}

resource "aws_lambda_function" "announcer" {
  function_name    = "botchat-announcer"
  role             = aws_iam_role.announcer.arn
  runtime          = "provided.al2023"
  handler          = "bootstrap"
  architectures    = ["arm64"]
  filename         = local.announcer_zip
  source_code_hash = filebase64sha256(local.announcer_zip)
  timeout          = 10
  memory_size      = 128

  environment {
    variables = {
      CHAT_NOTICES_QUEUE_URL = aws_sqs_queue.chat_notices.url
    }
  }
}

resource "aws_lambda_event_source_mapping" "announcer" {
  event_source_arn        = module.announcements.queue_arn
  function_name           = aws_lambda_function.announcer.arn
  batch_size              = 10
  function_response_types = ["ReportBatchItemFailures"]
}

Build the zip (Step 10.6) before terraform apply; source_code_hash makes Terraform redeploy whenever the zip changes.

11.4 Least-privilege credentials for the services

The game and chat run on Fly.io, outside AWS, so they need credentials. Give each its own IAM user that can do exactly one job.

infra/iam_services.tf
resource "aws_iam_user" "game_publisher" {
  name = "botchat-game-publisher"
}

resource "aws_iam_user_policy" "game_publisher" {
  user = aws_iam_user.game_publisher.name
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = "sns:Publish"
      Resource = aws_sns_topic.game_events.arn
    }]
  })
}

resource "aws_iam_user" "chat_consumer" {
  name = "botchat-chat-consumer"
}

resource "aws_iam_user_policy" "chat_consumer" {
  user = aws_iam_user.chat_consumer.name
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Action = [
        "sqs:ReceiveMessage",
        "sqs:DeleteMessage",
        "sqs:ChangeMessageVisibility",
        "sqs:GetQueueAttributes",
      ]
      Resource = [module.level_updates.queue_arn, aws_sqs_queue.chat_notices.arn]
    }]
  })
}

Create their access keys outside Terraform, so the secrets never land in the state file:

aws iam create-access-key --user-name botchat-game-publisher
aws iam create-access-key --user-name botchat-chat-consumer

Copy each key straight into your host's secret store (Step 13). Rotate them by creating a new key, deploying it, then deleting the old one.

Exercise: read a plan like a reviewer

Change maxReceiveCount to 3 in the module and run terraform plan. Find the two resources it changes and explain why both do. Then run terraform fmt -check and terraform validate; both will run in CI in Step 14. Finally, try terraform destroy followed by terraform apply, and confirm only queue URLs might change.

QA for this step

Automated

  • terraform fmt -check -recursive and terraform validate pass (they run in CI from Step 14).

Manual

  • Right after apply, terraform plan -detailed-exitcode exits 0 (no drift).
  • aws iam simulate-principal-policy denies botchat-game-publisher everything except sns:Publish on the topic.

Break it on purpose

  • Change a queue in the AWS console, then run plan: Terraform should show the drift and offer to undo it.

Checkpoint

terraform apply builds everything from scratch; a level-up flows topic → both queues → Lambda → chat-notices; and aws iam simulate-principal-policy shows botchat-game-publisher is denied sqs:ReceiveMessage.
