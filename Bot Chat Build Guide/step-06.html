Step 61 week

Connect chat to game

Make chat a gRPC client of the game: forward #games messages with SubmitInput, and hold a Subscribe stream open so GameServ's lines appear in the room.

Chat calls the game in one direction only. It forwards #games messages with SubmitInput, and it keeps one Subscribe stream open per game channel to receive what GameServ says. The game never calls chat.

Learn first

  • elixir-grpc on Hex and its docs. It's community-maintained and the client API changed around 1.0, so read the README for the version you install.
  • protobuf-elixir for code generation.
  • Task.Supervisor, especially async_nolink/2.
  • Process.send_after/3 for backoff timers.

6.2 One shared connection (full code)

gRPC runs over HTTP/2, which multiplexes many calls on one connection. Open it once and share it.

lib/chat/game/conn.ex
defmodule Chat.Game.Conn do
  @moduledoc "Holds the gRPC channel to the game service, connecting lazily."
  use GenServer

  def start_link(_), do: GenServer.start_link(__MODULE__, nil, name: __MODULE__)
  def get, do: GenServer.call(__MODULE__, :get)
  def reset, do: GenServer.cast(__MODULE__, :reset)

  @impl true
  def init(nil), do: {:ok, nil}

  @impl true
  def handle_call(:get, _from, nil) do
    case GRPC.Stub.connect(Application.fetch_env!(:chat, :game_addr)) do
      {:ok, channel} -> {:reply, {:ok, channel}, channel}
      {:error, reason} -> {:reply, {:error, reason}, nil}
    end
  end

  def handle_call(:get, _from, channel), do: {:reply, {:ok, channel}, channel}

  @impl true
  def handle_cast(:reset, _channel), do: {:noreply, nil}
end

6.3 Forwarding #games messages

lib/chat/game.ex
defmodule Chat.Game do
  require Logger
  alias Game.V1.{GameService.Stub, SubmitInputRequest}

  def metadata, do: %{"x-internal-token" => Application.fetch_env!(:chat, :game_token)}

  @doc "Fire-and-forget: never blocks the chat, never crashes the caller."
  def submit(room, user, text, msg_id) do
    Task.Supervisor.start_child(Chat.TaskSup, fn ->
      req = %SubmitInputRequest{
        channel: room,
        player_id: user.nick,          # nicks are unique and never change
        text: text,
        msg_id: to_string(msg_id)
      }

      with {:ok, channel} <- Chat.Game.Conn.get(),
           {:ok, _} <- Stub.submit_input(channel, req, metadata: metadata(), timeout: 2_000) do
        :ok
      else
        error ->
          Logger.warning("SubmitInput failed: #{inspect(error)}")
          Chat.Game.Conn.reset()
      end
    end)
  end
end

Then, in Chat.Rooms.post_message/3, after the broadcast:

if room == "games" and user.kind == "bot" do
  Chat.Game.submit(room, user, msg.body, msg.id)
end

The message ID doubles as the idempotency key: if a retry sends the same message twice, the game's runner counts it once.

6.4 The bridge: GameServ's voice in the room

A Chat.GameBridge process per game room holds the Subscribe stream open and posts each line as GameServ. Streams will drop (deploys, restarts, network blips), so reconnecting is the main job.

The stream is read inside a separate task, started with Task.Supervisor.async_nolink/2. "No link" means a crashing stream doesn't crash the bridge; the bridge just gets a :DOWN message and reconnects.

lib/chat/game_bridge.ex skeleton
defmodule Chat.GameBridge do
  use GenServer
  require Logger
  alias Game.V1.{GameService.Stub, SubscribeRequest}

  def start_link(room),
    do: GenServer.start_link(__MODULE__, room, name: {:via, Registry, {Chat.Registry, {:bridge, room}}})

  @impl true
  def init(room) do
    send(self(), :connect)
    {:ok, %{room: room, task: nil, last_seq: 0, backoff: 500, gameserv: nil}}
  end

  @impl true
  def handle_info(:connect, state) do
    parent = self()
    task = Task.Supervisor.async_nolink(Chat.TaskSup, fn -> stream_into(parent, state.room) end)
    {:noreply, %{state | task: task}}
  end

  # Exercise: handle {:game_message, msg}, the task finishing, and the task crashing.

  defp stream_into(parent, room) do
    {:ok, channel} = Chat.Game.Conn.get()
    req = %SubscribeRequest{channel: room}
    {:ok, stream} = Stub.subscribe(channel, req, metadata: Chat.Game.metadata(), timeout: :infinity)

    Enum.each(stream, fn
      {:ok, msg} -> send(parent, {:game_message, msg})
      {:error, error} -> exit({:stream_error, error})
    end)
  end
end

You'll also need Chat.Accounts.get_user_by_nick!/1 (Repo.get_by!(User, nick: nick)).

Exercise: finish the bridge

Add three handle_info/2 clauses:

  1. {:game_message, msg}: post msg.text to the room as the GameServ user (look it up once and keep it in state). If last_seq isn't 0 and msg.seq != last_seq + 1, log a warning about missed messages. Store the new seq and reset backoff to 500 ms.
  2. {ref, _result} where ref is the task's ref: the stream ended normally. Call Process.demonitor(ref, [:flush]), then schedule a reconnect.
  3. {:DOWN, ref, :process, _pid, reason} for the task's ref: the stream crashed. Log the reason and schedule a reconnect.

"Schedule a reconnect" means Process.send_after(self(), :connect, backoff) and doubling backoff, capped at 30 s.

Hint: matching the task's ref

A Task struct has a ref field. Pattern-match it in the function head so stray messages fall through: def handle_info({:DOWN, ref, :process, _, reason}, %{task: %Task{ref: ref}} = state). The same variable name in both places means "these must be equal".

Solution 
def handle_info({:game_message, msg}, state) do
  state = ensure_gameserv(state)

  if state.last_seq != 0 and msg.seq != state.last_seq + 1 do
    Logger.warning("#{state.room}: missed GameServ messages (#{state.last_seq} -> #{msg.seq})")
  end

  Chat.Rooms.post_message(state.room, state.gameserv, msg.text)
  {:noreply, %{state | last_seq: msg.seq, backoff: 500}}
end

def handle_info({ref, _result}, %{task: %Task{ref: ref}} = state) do
  Process.demonitor(ref, [:flush])
  reconnect(state)
end

def handle_info({:DOWN, ref, :process, _pid, reason}, %{task: %Task{ref: ref}} = state) do
  Logger.warning("#{state.room}: game stream down: #{inspect(reason)}")
  Chat.Game.Conn.reset()
  reconnect(state)
end

defp reconnect(state) do
  Process.send_after(self(), :connect, state.backoff)
  {:noreply, %{state | task: nil, backoff: min(state.backoff * 2, 30_000)}}
end

defp ensure_gameserv(%{gameserv: nil} = state),
  do: %{state | gameserv: Chat.Accounts.get_user_by_nick!("GameServ")}

defp ensure_gameserv(state), do: state

6.6 Authenticate every call

The Go server already rejects calls without x-internal-token (Step 5). The client sends it from Chat.Game.metadata/0 on every call. Both sides read the same secret from the environment (GAME_INTERNAL_TOKEN), so it never appears in code.

Exercise: test without a game server

Define a behaviour Chat.Game.Client with submit_input/2 and subscribe/1, make the real gRPC code one implementation, and use Mox to test that a bot message in #games calls submit_input exactly once with the message ID, and that a message in #python doesn't call it at all.

QA for this step

Automated

  • Mox tests: a bot message in #games calls submit_input once with the message ID; a message in #python doesn't call it.
  • A bridge test using a fake stream that ends: the bridge schedules a reconnect and doubles its backoff.

Manual

  • Run the smoke test locally: it passes 3 times in a row.

Break it on purpose

  • Restart the game mid-match: the bridge reconnects within a few seconds and logs a seq gap. Stop it for a minute: backoff grows to 30 s and no CPU is wasted.

Checkpoint

Two test bots (a short script on the internal socket is enough) can play a full match in #games, and stopping and restarting the Go service makes the bridge reconnect on its own within a few seconds, with a warning about missed messages in the log.
