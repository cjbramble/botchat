Step 91–2 weeks

"Events: SNS, SQS and Broadway"

Award XP in the game's own database, publish player.leveled_up to SNS, and consume it in chat with Broadway so level badges update live.

The game owns XP. When a player levels up, it publishes one event to an SNS topic; SNS copies it into every subscribed SQS queue; chat consumes one of those queues and updates its cached level. That's the sync-plus-async pair from the concepts primer: chat asks for a level once with GetPlayer, then events keep it fresh.

Learn first

  • SQS as an SNS subscriber and raw message delivery.
  • Visibility timeout and dead-letter queues.
  • AWS SDK for Go v2: getting started and pgx for Postgres.
  • Broadway's Amazon SQS guide and BroadwaySQS.Producer.
  • Transactional outbox: read now, build as a stretch goal.

9.2 XP and levels (full code)

internal/xp/xp.go
// Package xp turns match results into experience points and levels.
package xp

import "math"

const (
    RoundWin = 20
    ExactHit = 30 // on top of RoundWin
    MatchWin = 50
)

// LevelFor: level 1 at 0 XP, level 2 at 50, level 3 at 200, level 4 at 450...
func LevelFor(xp int64) int {
    if xp < 0 {
        xp = 0
    }
    return int(math.Sqrt(float64(xp)/50)) + 1
}

package xp

import "testing"

func TestLevelFor(t *testing.T) {
    cases := []struct {
        xp   int64
        want int
    }{
        {0, 1}, {49, 1}, {50, 2}, {199, 2}, {200, 3}, {450, 4}, {-10, 1},
    }
    for _, tc := range cases {
        if got := LevelFor(tc.xp); got != tc.want {
            t.Errorf("LevelFor(%d) = %d, want %d", tc.xp, got, tc.want)
        }
    }
}

Exercise: an XP store with pgx

Write internal/store with:

  • AddXP(ctx, playerID string, delta int64) (oldLevel, newLevel int, err error) using one SQL statement, so two concurrent awards can't lose an update.
  • GetXP(ctx, playerID string) (int64, error), returning 0 for unknown players.

Then implement GetPlayer in the gRPC server with it.

Hint: an atomic upsert

INSERT ... ON CONFLICT (player_id) DO UPDATE SET xp = players.xp + EXCLUDED.xp RETURNING xp adds and returns the new total in one round trip. The old level is LevelFor(newXP - delta).

Solution 
type Store struct{ db *pgxpool.Pool }

func (s *Store) AddXP(ctx context.Context, playerID string, delta int64) (int, int, error) {
    var total int64
    err := s.db.QueryRow(ctx, `
        INSERT INTO players (player_id, xp) VALUES ($1, $2)
        ON CONFLICT (player_id) DO UPDATE SET xp = players.xp + EXCLUDED.xp, updated_at = now()
        RETURNING xp`, playerID, delta).Scan(&total)
    if err != nil {
        return 0, 0, fmt.Errorf("add xp for %s: %w", playerID, err)
    }
    return xp.LevelFor(total - delta), xp.LevelFor(total), nil
}

9.4 A publisher interface

The game shouldn't care whether events go to SNS, a log, or a test spy. One small interface, three implementations.

internal/events/events.go
package events

import (
    "context"
    "encoding/json"
    "log/slog"
    "time"

    "github.com/aws/aws-sdk-go-v2/aws"
    "github.com/aws/aws-sdk-go-v2/service/sns"
    "github.com/aws/aws-sdk-go-v2/service/sns/types"
    "github.com/google/uuid"
)

type LevelUp struct {
    EventID    string    `json:"event_id"`
    Type       string    `json:"type"`
    Version    int       `json:"version"`
    OccurredAt time.Time `json:"occurred_at"`
    PlayerID   string    `json:"player_id"`
    OldLevel   int       `json:"old_level"`
    NewLevel   int       `json:"new_level"`
}

func NewLevelUp(player string, oldLevel, newLevel int) LevelUp {
    return LevelUp{EventID: uuid.NewString(), Type: "player.leveled_up", Version: 1,
        OccurredAt: time.Now().UTC(), PlayerID: player, OldLevel: oldLevel, NewLevel: newLevel}
}

type Publisher interface {
    Publish(ctx context.Context, e LevelUp) error
}

// LogPublisher is for local dev and tests without AWS.
type LogPublisher struct{}

func (LogPublisher) Publish(_ context.Context, e LevelUp) error {
    slog.Info("event", "type", e.Type, "player", e.PlayerID, "level", e.NewLevel)
    return nil
}

// SNSPublisher sends to a real topic. The "type" attribute lets subscriptions filter.
type SNSPublisher struct {
    Client   *sns.Client
    TopicARN string
}

func (p SNSPublisher) Publish(ctx context.Context, e LevelUp) error {
    body, err := json.Marshal(e)
    if err != nil {
        return err
    }
    _, err = p.Client.Publish(ctx, &sns.PublishInput{
        TopicArn: aws.String(p.TopicARN),
        Message:  aws.String(string(body)),
        MessageAttributes: map[string]types.MessageAttributeValue{
            "type": {DataType: aws.String("String"), StringValue: aws.String(e.Type)},
        },
    })
    return err
}

Choose the implementation in main.go from an env var: EVENTS=sns builds the SNS client with config.LoadDefaultConfig(ctx); anything else uses LogPublisher.

9.5 Award XP off the match goroutine

Database and network calls must not run on the runner goroutine: a slow database would freeze every turn timer. Send results to a separate awarder goroutine instead.

Exercise: the awarder

In the hub, on match.RoundWon and match.MatchWon, send an award{player, delta} value to a buffered channel (size 100). A single awarder goroutine reads it, calls store.AddXP, and if newLevel > oldLevel, publishes events.NewLevelUp(...) with a 5 s context timeout. Log failures; don't crash. A round win is worth xp.RoundWin, plus xp.ExactHit for an exact hit; a match win adds xp.MatchWin.

The gap you're leaving (on purpose)

If the process dies after AddXP commits but before Publish succeeds, the level-up event is lost and chat's badge stays stale until the next GetPlayer. The fix is the transactional outbox: write the event to an outbox table in the same transaction, and publish from there. Note it in your README; build it later.

9.6 Consume it in chat with Broadway

You need the real topic and queues now. Either create them by hand as in Step 8.5 (topic game-events; queue level-updates with raw delivery and a filter on type), or jump ahead and apply the first part of the Terraform in Step 11, which is the better habit.

Follow the BroadwaySQS README for any extra parser dependency your version needs, then configure AWS credentials from the environment:

config/runtime.exs add
config :ex_aws,
  access_key_id: System.get_env("AWS_ACCESS_KEY_ID"),
  secret_access_key: System.get_env("AWS_SECRET_ACCESS_KEY"),
  region: System.get_env("AWS_REGION", "us-east-1")
lib/chat/level_consumer.ex
defmodule Chat.LevelConsumer do
  use Broadway
  require Logger

  def start_link(_opts) do
    Broadway.start_link(__MODULE__,
      name: __MODULE__,
      producer: [
        module: {BroadwaySQS.Producer, queue_url: System.fetch_env!("LEVEL_QUEUE_URL")},
        concurrency: 1
      ],
      processors: [default: [concurrency: 2]]
    )
  end

  @impl true
  def handle_message(_processor, %Broadway.Message{data: data} = message, _context) do
    case Jason.decode(data) do
      {:ok, %{"type" => "player.leveled_up", "version" => 1, "player_id" => nick, "new_level" => level}} ->
        Chat.Accounts.bump_level_cache(nick, level)
        message

      {:ok, other} ->
        Logger.warning("ignoring unknown event: #{inspect(Map.take(other, ["type", "version"]))}")
        message

      {:error, reason} ->
        Broadway.Message.failed(message, reason)  # not deleted: SQS retries, then the DLQ
    end
  end
end

Add Chat.LevelConsumer to your supervision tree, but only when LEVEL_QUEUE_URL is set, so local dev without AWS still boots.

Exercise: an idempotent, order-proof update

Write Chat.Accounts.bump_level_cache(nick, level) so that running it twice, or running an old event after a newer one, changes nothing. When it does change a row, broadcast {:level_changed, nick, level} on a "levels" PubSub topic, and have the viewer's nick list show levels from it.

Hint

Put the guard in the SQL: from(u in User, where: u.nick == ^nick and u.level_cache < ^level) |> Repo.update_all(set: [level_cache: level]). update_all returns {count, nil}; broadcast only when count == 1.

9.7 Seed badges with GetPlayer

When a bot first joins (in RoomChannel's :after_join), call GetPlayer over gRPC and bump_level_cache with the answer. Events keep it fresh after that. If the game is down, skip it: the badge is a cache, and the next event fixes it.

QA for this step

Automated

  • Unit tests for LevelFor and the awarder (with a fake store and a spy publisher).
  • An ExUnit test that bump_level_cache/2 is idempotent and ignores older levels.

Manual

  • Run the event path checks: duplicate, out-of-order and malformed events.

Break it on purpose

  • Stop Postgres for the game during a match: awards fail and are logged, the match itself keeps running.

Checkpoint

A bot levels up and the viewer shows its new [Lv N] within about a second; sending the same SQS message twice by hand (aws sqs send-message) changes nothing the second time; and a malformed message ends up in the dead-letter queue after 5 receives.
